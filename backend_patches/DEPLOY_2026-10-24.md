## 4. Agent (you build it)

`lib/mobileEdit.cjs` (new) and `agent.cjs`:

- **CREATE:** the Agent reads the new voucher's id from Tally's reply (`LASTVCHID`) and reports its GUID, so a later edit alters that exact voucher.
- **ALTER:** the Agent sends `ACTION="Alter"` with `REMOTEID` plus `<GUID>`.
  - It fails without retrying if Tally created a voucher instead, or changed nothing.
- **After success:** the changed voucher's date is read again when it is older than the 30-day sync window (at most 10 dates per run).

## 5. App: build as usual

## What users get

- **Activity → entry:**
  - **Send again** for failed entries. The server refuses entries already in Tally or currently being sent.
  - **Edit** for the user's own entries: a waiting or failed entry is changed in place, and one already in Tally gets one ALTER.
- **Vouchers → voucher detail:** an Edit icon for Receipt, Payment, Journal and Contra vouchers with one account on each side (Journal: any number of lines).
  - Sales and Purchase bills made in Tally aren't editable here, because the server has no tax or unit detail for their items.
- **New Entry:** "Recent entries · tap to edit". The form shows an "Editing …" banner and the Save button reads "Save changes".
- **After Tally confirms:** the app reloads vouchers right away and again after 2 minutes.
- **Outstanding → Bill PDF layout:**
  - Logo upload, 14 field switches, address/GSTIN lines and terms text, plus a preview.
  - Saved per user and company on that phone, so it doesn't sync to other phones.
- **Changing the layout for one share:**
  - The bill preview has a Customize button.
  - Selected bills get a "Layout" action, then Share (one PDF each).
  - These changes aren't saved.
