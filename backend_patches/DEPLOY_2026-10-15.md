### Agent settings (Windows environment variables on the Tally PC)

| Variable | Default | Meaning |
|---|---|---|
| `FIN_SYNC` | (on) | `off` skips the financial step completely |
| `FIN_STOCK_FROM_TALLY` | (off) | `1` lets the Agent ask Tally for the closing stock at year and month ends: one per sync, 90-second limit, 7-day pause if slow. Set it only after the test in step 4 |
| `FIN_TALLY_ANCHOR` | (off) | `1` only if entries are synced from a later date than the books begin |

Set one with, for example, `setx FIN_STOCK_FROM_TALLY 1`, then restart the Agent.
If the Agent runs as a Windows service, set it as a system variable (`setx /M ...`)
and restart the service.

### What the Agent does by default
- **Light requests only**, once a day: the group list, the books-beginning date and
  the items' opening values. No balances and no periods.
- **No request before the books begin.** That request is what froze Tally on
  "GI Apr 25-26".

## 4. One-time Tally test (before switching on closing stock)

Do this on the Tally PC, outside business hours, with the company open in Tally and
the Agent stopped:
```powershell
cd C:\Users\AVERLON\Downloads\tally-agent
node tools\fin-probe.cjs "GI Apr 25-26"
```
It times each request, with a 120-second limit per request, and prints a
recommendation:
- **"All quick"** → set `FIN_STOCK_FROM_TALLY=1`, restart the Agent and let it sync a
  few times. The year-end closing stock comes first.
- **"Closing stock is slow"** → leave it off and send the output to support.

## 5. What users see in Reports
- **Not ready yet:** the reason instead of a general message. For example: "Closing
  stock values are not synced yet …", or "Entries are synced from a later date than
  the start of your books …".
- **"GI Apr 25-26" and similar companies:** P&L and Balance Sheet need Tally's
  closing stock at 31-03-2026. They appear once `FIN_STOCK_FROM_TALLY=1` has fetched
  it, normally on the first sync after you switch it on.
